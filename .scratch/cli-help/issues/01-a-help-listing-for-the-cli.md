# 01 — A help listing for the CLI

Status: done

The binary has no help. `main.go` dispatches on a bare `switch` with no `help`
case and no `flag` usage, so `organizer help`, `organizer -h` and
`organizer --help` all fall through to `default:` and print
`error: unknown command: help`, exit 1. An unknown command prints only itself —
never the list of real ones. The individual subcommands print a `usage:` line,
but only once you have already guessed the name and got its arguments wrong.

There is, in other words, no way to find out what the tool can do except reading
`cmd/organizer/main.go`.

## Decisions (grill-with-docs, 2026-08-12)

Raised by the maintainer during the [[trainer-offboarding]] grill, which is what
made it pressing: that ticket takes the CLI from six subcommands to ten.

**Both `help` and `-h`/`--help`**, all three to `stdout`, exit 0. Requested help
is not an error — `organizer help | less` should show something, and a non-zero
exit turns it into a failure inside any script. Three `case` labels in the
existing `switch`; the `flag` package is not needed for this and would run
against ADR-0002's stack minimalism.

**Three groups: `Accounts`, `Data`, `Development`.** Ten subcommands as a flat
list is a wall. `seed-demo` and `clear-demo` stay listed rather than hidden — a
hidden command is worse than a visible one, because whoever eventually finds it
finds it without the heading that says what it is for. One line each: name,
arguments, half a sentence.

**An unknown command keeps its current message** on `stderr` with exit 1, and
gains one line: `run: organizer help`. Dumping the full listing after a typo
would push the actual error off the screen, and it is what gives the `help`
command a job.

**English**, per [[cli-language]] 01: the operator-facing half of the CLI is
English, and a help listing is as operator-facing as it gets. Nothing here goes
through `internal/i18n`.

**Running with no arguments still starts the server.** Unchanged — that is the
deployment entry point (ADR-0002, Fly), so the listing cannot live there.

## Ordering

**Pre-deployment scope**, decided with [[trainer-offboarding]] 01 on 2026-08-12.

Not blocked by, and not blocking, [[trainer-offboarding]] 01. If that ticket
lands first this listing covers ten subcommands; if this one lands first, that

## Acceptance

- `organizer help`, `organizer -h` and `organizer --help` all print the listing to
  `stdout` and exit 0.
- The listing groups subcommands under `Accounts`, `Data` and `Development`, one
  line each with arguments and a short description.
- **Every subcommand in the `switch` appears in the listing.** A test that walks
  the dispatcher's known commands and asserts each one is present, so the next
  subcommand cannot be added without its line — a listing that silently goes stale
  is worse than none.
- An unknown command still prints `unknown command: <name>` to `stderr` and exits
  1, now followed by a line pointing at `organizer help`.
- `organizer` with no arguments still starts the server; a test or an explicit
  note confirms this path was not touched.
- The listing is English and contains no catalog lookups.
- `go test ./...` passes.

## Comments

2026-08-14 — Implemented. `helpText` and `isHelpRequest` live in
`cmd/organizer/help.go`, the tests in `cmd/organizer/help_test.go`.

Two deviations from the decisions above, both from the code review:

- **Help is answered before `config.Load()`, not as three `case` labels in the
  switch.** With the labels in the switch, `ORGANIZER_SESSION_LIFETIME=abc
  organizer help` printed a configuration error and exited 1 — a broken
  environment is exactly when somebody reaches for the listing. The three
  spellings now sit in `isHelpRequest`, checked at the top of `run`. Still no
  `flag` package.
- **The listing carries a `Usage:` header and a fourth `Help:` group** beyond
  `Accounts`, `Data` and `Development`. The three groups were about the
  subcommands; with the help spellings out of the switch, that fourth group is
  the only place they are written down.

The completeness test parses `main.go` with `go/parser` and reads the case
labels out of the dispatcher's switch, so the listing cannot go stale silently.
Verified by mutation: a `case "seed"` added to the switch fails the test even
though the string `seed` already occurs inside the `seed-demo` line.

The no-argument path is untouched — the guard is still `len(args) > 0` — and is
noted rather than tested, since `serve` blocks until a signal.
